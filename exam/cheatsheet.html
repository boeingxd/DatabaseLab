Keys

TRAPS · DESIGN
  • FK lives on the MANY side, never on the "one" side.
  • M:N cannot be stored with one FK: needs a junction table.
  • Composite PK: the PAIR is unique; each column alone may repeat.
  • Single-column PK + 1NF ⇒ already 2NF (2NF only bites with a composite key).
  • UNIQUE ≠ PK: UNIQUE accepts NULL, PK never does.

Subqueries

-- IN: students who have an enrolment
SELECT name FROM students
WHERE id IN
  (SELECT student_id FROM enrolments);
-- EXISTS: same answer, row by row
SELECT name FROM students s
WHERE EXISTS (SELECT 1 FROM enrolments e
              WHERE e.student_id = s.id);

"Has none" (anti-join), 3 ways:

-- 1 NOT EXISTS (always safe)
SELECT name FROM students s
WHERE NOT EXISTS
  (SELECT 1 FROM enrolments e
   WHERE e.student_id = s.id);
-- 2 LEFT JOIN ... IS NULL
SELECT s.name FROM students s
LEFT JOIN enrolments e
       ON e.student_id = s.id
WHERE e.id IS NULL;
-- 3 NOT IN (only if no NULL in list)
SELECT name FROM students
WHERE id NOT IN
  (SELECT student_id FROM enrolments
   WHERE student_id IS NOT NULL);
TRAPS · QUERIES
  • LEFT JOIN + COUNT(*) counts the NULL-filled row → 1 for "no match". COUNT(e.id) → 0.
  • NOT IN with a NULL in the list returns NOTHING: 3 NOT IN (1, 2, NULL) is UNKNOWN. Use NOT EXISTS.
  • WHERE cannot use aggregates (WHERE COUNT(*) > 1 ✗ → HAVING) or SELECT aliases (WHERE n > 1 ✗).
  • BETWEEN is inclusive at both ends.
  • = NULL is never true → IS NULL.
  • Condition on the RIGHT table in WHERE turns a LEFT JOIN into INNER; put it in ON.
  • UPDATE / DELETE without WHERE hits every row.
  • LIKE with no % or _ behaves like =.

VIEW

CREATE VIEW order_details AS
SELECT o.id AS order_id, c.name,
       b.title, o.quantity,
       o.quantity * b.price AS total
FROM orders o
JOIN customers c ON c.id = o.customer_id
JOIN books b     ON b.id = o.book_id;

SELECT * FROM order_details
WHERE total > 1000;
DROP VIEW order_details;
  • Stores the QUERY, not the data (a saved SELECT with a name).
  • Always shows the CURRENT base tables: new order → appears in the view at once.
  • Queried like a table. CREATE OR REPLACE VIEW changes it.
TRAPS · OBJECTS
  • MODIFY replaces the WHOLE definition: restate NOT NULL / DEFAULT or they are lost.
  • Create parent before child; drop child before parent.
  • FK column type must match the parent PK (BIGINT ↔ BIGINT).
  • Default ON DELETE is RESTRICT, not CASCADE.
  • A view is not a snapshot or copy; it reruns its query each time.
  • AUTO_INCREMENT numbers are not reused (gaps are normal).

4 · PROCEDURES · TRIGGERS · TRANSACTIONS

DELIMITER //
CREATE PROCEDURE place_order(
  IN p_customer INT, IN p_book INT,
  IN p_qty INT, OUT p_order_id INT)
BEGIN
  DECLARE v_stock INT;  -- DECLARE first
  SELECT stock INTO v_stock
    FROM books WHERE id = p_book;
  IF v_stock IS NULL THEN
    SIGNAL SQLSTATE '45000'
      SET MESSAGE_TEXT = 'no such book';
  ELSEIF v_stock < p_qty THEN
    SET p_order_id = 0;  -- not enough
  ELSE
    UPDATE books
       SET stock = stock - p_qty
     WHERE id = p_book;
    INSERT INTO orders
      (customer_id, book_id, quantity)
    VALUES (p_customer, p_book, p_qty);
    SET p_order_id = LAST_INSERT_ID();
  END IF;
END //
DELIMITER ;
CALL place_order(1, 5, 2, @oid);
SELECT @oid;

Trigger

DELIMITER //
CREATE TRIGGER after_enrolment_insert
AFTER INSERT ON enrolments
FOR EACH ROW
BEGIN
  UPDATE courses SET seats = seats - 1
   WHERE id = NEW.course_id
     AND seats > 0;
  IF ROW_COUNT() = 0 THEN
    SIGNAL SQLSTATE '45000'
    SET MESSAGE_TEXT = 'course is full';
  END IF;
END //
DELIMITER ;
EventOLD.colNEW.col
INSERTnoyes (new row)
UPDATEyes (before)yes (after)
DELETEyes (deleted row)no
  • 6 kinds: BEFORE / AFTER × INSERT / UPDATE / DELETE.
  • BEFORE: check or change the row (IF NEW.quantity <= 0 THEN SIGNAL.., SET NEW.x = ..). AFTER: update OTHER tables.
  • FOR EACH ROW: body runs once per affected row.
  • SIGNAL SQLSTATE '45000' = user error (Error 1644): cancels the statement that fired the trigger.
  • Fires automatically, cannot be CALLed. SHOW TRIGGERS;

Transaction

START TRANSACTION;
UPDATE courses SET seats = seats - 1
 WHERE id = 1 AND seats > 0;
INSERT INTO enrolments
  (student_id, course_id) VALUES (3, 1);
COMMIT;      -- keep both
-- or ROLLBACK;  -- undo both
AtomicityAll statements happen, or none
ConsistencyValid state → valid state; constraints hold
IsolationOthers never see uncommitted changes
DurabilityAfter COMMIT it survives a crash
TRAPS · PROGRAMMABILITY
  • A failed statement undoes only ITSELF. Earlier statements stay until you ROLLBACK.
  • No START TRANSACTION = autocommit: each statement is saved at once; ROLLBACK does nothing.
  • INSERT trigger has no OLD; DELETE has no NEW.
  • ELSEIF not ELSE IF; DECLARE must come first.

Transaction pattern

const conn = await pool.getConnection();
try {
  await conn.beginTransaction();
  const [u] = await conn.execute(
    'UPDATE books SET stock = stock - ? '
    + 'WHERE id = ? AND stock >= ?',
    [quantity, book_id, quantity]);
  if (u.affectedRows === 0) {
    await conn.rollback();
    return res.status(409).json(
      { error: 'not enough stock' });
  }
  const [r] = await conn.execute(
    'INSERT INTO orders (customer_id, '
    + 'book_id, quantity) VALUES (?,?,?)',
    [req.params.id, book_id, quantity]);
  await conn.commit();
  res.status(201).json(
    { order_id: r.insertId });
} catch (err) {
  await conn.rollback();
  res.status(500).json(
    { error: err.message });
} finally {
  conn.release();  // always runs
}

6 · SECURITY & PERFORMANCE

// UNSAFE: input glued into the SQL
const sql = "SELECT * FROM books "
  + "WHERE author = '" + author + "'";
// attack input:  ' OR '1'='1
// → WHERE author = '' OR '1'='1'
//   always true: returns EVERY row
// SAFE: ? placeholder, value separate
pool.execute('SELECT * FROM books '
  + 'WHERE author = ?', [author]);

Safe: the value is always DATA, never SQL.

TRAPS · SECURITY & PERFORMANCE
